## 项目简介
这是一个自动化打卡脚本，旨在帮助用户完成B站的每日签到任务，包括分享视频、观看视频、~~直播签到~~、漫画签到、自动投币。通过使用GitHub Actions，可以实现每日自动运行脚本，完成签到任务并获取相应的奖励。  

## 包含功能:
1. **任务签到**：登录奖励、分享奖励、观看视频、~~直播签到~~(活动已下线,功能暂时保留)、漫画签到、视频投币等任务；
2. **支持多账号**：可在单个工作流中为多个账号执行任务；
3. **安全可靠**：敏感信息安全传递：支持通过环境变量读取cookie；
4. **自动化运行**：结合GitHub Actions实现自动化运行，执行日志结果清晰；
5. **支持通过 PushPlus 推送任务运行结果**，方便及时获取通知；
6. **手动触发**：(每日奖励只能领取一次，故触发多次即使执行成功结果也不会变化)。

## 使用方法:  
1. Fork本项目到你的GitHub仓库中。
2. 在你的仓库 `Settings -> Secrets and variables -> Actions` 中，添加以下 `Repository secrets`：


 | 名称 | 是否必需 | 说明 | 默认值 |
|---|---|---|---|
 | `BILIBILI_COOKIE` | **是** | B站Cookie。多账号用 `###` 分隔。建议包含`buvid3`字段以降低风控风险 | 无 |
 | `PUSH_PLUS_TOKEN` | **否** | PushPlus 的 Token，用于推送通知。 | 无 |
 | `TASK_CONFIG` | **否** | 任务执行控制，用逗号分隔。可选值: `manga_sign`(漫画签到), `share_video`(分享), `add_coin`(投币), `live_sign`(直播签到，官方已下线，仅保留兼容) | `manga_sign,share_video,add_coin` |
 | `COIN_ADD_NUM` | **否** | 每日投币数量。`max` = 自动投满每日经验上限（先查今日已得经验，只补投差额，推荐）；数字 N = 固定投 N 枚（上限5）；`0` = 关闭投币 | `max` |
 | `COIN_SELECT_LIKE`| **否** | 投币时是否点赞。`1` 为是，`0` 为否。 | `1` |
 | `COIN_VIDEO_SOURCE`| **否** | 投币视频来源。`dynamic` (分区最新)，`ranking` (排行榜)，`popular` (综合热门)。单一来源获取失败时自动回退到其他来源。 | `dynamic` |

   **多账号Cookie配置示例:**
   cookie账号1###cookie账号2###cookie账号3
   ![image](docs/images/img03.png)


3. 启用GitHub Actions，Fork的仓库默认是关闭workflow的，需要手动开启。

## 注意事项:  
1. Cookie要包含`bili_jct`, `SESSDATA`, `DedeUserID`字段；
2. 建议先手动运行测试；
3. 可以根据需要修改cron表达式调整执行时间；  
4. 请确保Cookie有效，修改密码或退出登录会导致Cookie失效；  
5. 请勿在任何位置明文泄露你的Cookie以防账号被盗；  
6. **为了保护用户隐私，执行日志中的用户名等信息将进行脱敏处理（例如 `U******e`），请放心使用**；
7. 本项目仅供学习交流使用，请勿滥用。

## 常规问题：  
1. 关于分享视频：  
- 这个分享操作是调用B站的分享接口，实际上只是模拟了一次分享行为；
- 不会真实分享到任何地方，只是为了完成每日任务获取经验值；
- B站会记录这个分享行为，但不会在任何地方显示出来。

2. 关于观看视频：  
- 程序里指定的视频BV号是随意挑选的(侵联删!)，不指定特定BV号也是可以的；
- 当前代码指定BV号主要是为了保证稳定性，因为随机视频可能会遇到:  
-- 视频已下架  
-- 视频需要会员才能观看   
-- 视频有年龄限制等情况  
- 当前默认优先使用动态视频列表的第一个视频，只有获取失败时才用指定的固定BV号。  

3. 关于投币任务：
- B站规则：每投币1枚+10经验，每日投币经验上限5枚/50经验（另有登录/观看/分享各+5）；
- 默认 `max` 模式：自动查询今日已得投币经验，只补投差额枚数，确保每天稳定拿满50投币经验，不浪费硬币；例如今日已得20经验则补投3枚；
- 若设置固定数字 N，则每天固定投 N 枚；设 `0` 关闭投币；
- 硬币余额不足时自动降为按余额投，并打印 WARNING 提示；
- 如果当天投币已达上限或经验已满，自动终止并提示“跳过”，不影响任务成败；
- 投币目标视频可选“分区最新/综合热门/排行榜”三种来源（`COIN_VIDEO_SOURCE`环境变量控制），单一来源获取失败会自动回退到其他来源，候选池扩大到20~100个视频，已投过硬币的视频自动跳过；
- 投币动作之间加了随机间隔，降低风控风险；
- 投币任务失败不会影响其他任务的执行。

4. 关于任务执行一致性： 
- 所有账号会严格按照`TASK_CONFIG`配置执行任务，未配置按默认执行； 
- 即使某些任务被跳过(如未配置、硬币不足、活动下线、今日已签到/已领取)，也会以 WARNING 级别打印日志，不影响任务成败判定； 
- PushPlus推送失败不影响整体任务成功，为非必需配置； 
- 每个账号只要有一个登录后任务成功，则该账号整体成功；
- 如果账号登录失败或所有任务都失败，则该账号失败；
- 多账号时，只要有一个账号失败，整体失败；
- 整体失败则会触发任务失败通知(需开启邮件通知)。

5. 关于稳定性设计（面向GitHub Actions长期自动运行）： 
- 所有API请求带 15 秒超时，网络异常/风控拦截(code -412)自动重试 3 次（梯度退避）；
- 使用 requests.Session 复用连接，减少握手开销；
- 任务间/账号间加随机间隔(1~4秒)，模拟正常用户节奏降低风控风险；
- 漫画签到已做幂等处理：重复执行时“已签到”不会被误判为失败；
